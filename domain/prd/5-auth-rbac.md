# PRD-005：登入與 RBAC 權限設計

> 版本：v0.2
> 日期：2026-08-11
> 狀態：草稿

---

## 1. 背景與目標

willThx 後台的使用者為廠內系統工程師，需要一套帳號登入與角色權限機制，確保不同職責的工程師只能存取對應的功能與資料。支援動態功能選單，讓新功能上線時不需修改程式碼，僅透過後台設定即可完成上架。

---

## 2. 使用者與角色

| 角色 | 說明 |
|------|------|
| **Admin** | 自動擁有所有功能，不需設定。不受製程站點限制，永遠看全部資料。 |
| **Maintainer** | 可查看所有資料、執行製程配置與告警規則的寫入操作、Acknowledge 告警。可被限制只看指定製程站點的資料。不可進行使用者管理。 |
| **Viewer** | 唯讀，僅能查看 Dashboard、告警、資料查詢，不可執行任何寫入操作。可被限制只看指定製程站點的資料。 |

一個使用者只能擁有一個角色。

---

## 3. 操作流程

### 3.1 登入

使用者輸入帳號與密碼登入。驗證通過後，系統依據角色查出可存取的子功能清單，組成功能樹（Feature Tree）回傳前端，前端依此動態渲染側邊選單（Sidebar）。帳號停用者直接拒絕登入。

### 3.2 帳號建立

Admin 在使用者管理頁面建立帳號，設定帳號名稱、顯示名稱、角色，並可選填製程站點綁定。第一個 Admin 帳號由系統初始化時手動建立。

### 3.3 製程站點綁定

Admin 在新增或編輯使用者時，可為 Maintainer / Viewer 指定一或多個製程站點。指定後，該使用者所有畫面的資料視圖均自動套用站點篩選，只顯示對應站點的資料。未指定任何站點則視為可看全部站點。

### 3.4 功能管理

Admin 在功能管理頁面維護系統的功能清單，建立父功能（選單群組）與子功能（實際頁面）的樹狀結構。子功能需設定路由（對應前端頁面）與排序。權限設定只作用於子功能。

### 3.5 角色權限設定

Admin 在角色權限設定頁面，以矩陣方式為 Maintainer 和 Viewer 勾選可存取的子功能。Admin 角色自動擁有所有功能，欄位顯示為唯讀。新功能上線時需手動執行此步驟一次。

### 3.6 登出

使用者點擊登出後，前端清除本地 session，跳轉回登入頁。後端使當前的 refresh token 失效，無法再換取新的 access token。

### 3.7 帳號停用

Admin 停用帳號後，對方的現有登入 session 立即失效，無法繼續操作。

---

## 4. 業務規則

- Admin 自動擁有所有功能，角色權限設定頁面中 Admin 欄位唯讀，不可修改
- 父功能下若無該角色可存取的子功能，父功能的選單群組標題自動隱藏
- Admin 不可修改自己的角色，防止自我降權
- 系統至少保留一個有效的 Admin 帳號，停用最後一個 Admin 時系統拒絕操作
- 帳號停用保留歷史資料，不實體刪除
- 角色權限設定變更後，次次登入時生效，對已登入的使用者不立即影響
- 子功能刪除時，所有角色中已綁定該功能的權限一併移除
- 製程站點綁定為空（未設定）= 可看全部站點；設定後只看指定站點
- 製程站點綁定對 Admin 無效，Admin 永遠看全部
- 各角色使用者可修改自己的基本資訊（顯示名稱、密碼）（TODO：個人帳號設定頁面待後續設計）
- 密碼重設由 Admin 操作（TODO：具體流程待後續設計）

## 5. 例外處理

| 情境 | 系統行為 |
|------|---------|
| 帳號不存在或密碼錯誤 | 回傳統一錯誤訊息，不區分帳號或密碼錯誤 |
| 帳號已停用嘗試登入 | 提示「帳號已停用，請聯繫管理員」 |
| 嘗試停用最後一個 Admin | 拒絕，提示「至少需保留一個有效的 Admin 帳號」 |
| Admin 嘗試修改自己的角色 | 拒絕，提示「不可修改自己的角色」 |
| 角色無任何可存取的子功能 | 登入成功，但 Sidebar 無選單項目 |
| 子功能被刪除 | 該功能從所有角色的權限中移除，下次登入後 Sidebar 不再顯示 |
