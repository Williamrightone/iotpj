# PRD-002：Web SaaS 功能收斂

> 版本：v0.1
> 日期：2026-08-07
> 狀態：草稿

---

## 1. 概述

本文件定義 **willThx** Web SaaS 平台提供的功能範圍，並說明每項功能如何對應 PRD-001 的業務需求。

### 1.1 功能目標

| PRD-001 需求 | willThx 對應功能 |
|------------|----------------|
| 3.1 板件履歷追溯 | M4 資料查詢（板件追溯、批號查詢） |
| 3.2 異常即時告警分派 | M2 Dashboard 告警列表、M3 告警中心 |
| 3.3 資料查詢與復盤 | M4 資料查詢（感測數值展開、AOI 複判記錄） |

### 1.2 即時資料傳輸策略

| 場景 | 技術 | 說明 |
|------|------|------|
| 感測器折線圖（Telemetry） | WebSocket | 高頻連續推送，低延遲 |
| 告警即時通知 | WebSocket | 事件驅動，不可遺漏 |
| Dashboard 統計卡（批號進度、在線機台數） | Polling（30s） | 低頻摘要，不需即時 |
| 歷史查詢 / 追溯 / 設定 | REST API | 一次性請求 |

## 2. RBAC 角色定義

平台設有三種角色，一個使用者只能擁有一種角色：

| 角色 | 說明 |
|------|------|
| **Admin（管理員）** | 可執行所有操作，包含平台設定、使用者管理、告警規則設定 |
| **Operator（操作員）** | 可查看所有資料、操作告警（Acknowledge），不可修改設定 |
| **Viewer（觀察者）** | 唯讀，僅能查看 Dashboard、告警、資料查詢，不可執行任何寫入操作 |

## 4. 功能模組說明

### M1 — 製程配置

> **目的**：讓 Admin 自助建立工廠的靜態設定層級（Station → Machine → IoT Component）。
> **可見角色**：所有角色（Operator / Viewer 唯讀）

#### 4.1.1 站點管理

- 新增 / 編輯 / 刪除製程站點
- 設定站點名稱、站點代碼、站點順序（可拖拉排序，決定製程流向）
- 在站點層級直接新增 IoT 元件（e.g., 站區溫濕度感測器、電表）

#### 4.1.2 機台管理

- 選擇站點後，檢視該站所有機台
- 新增 / 編輯 / 刪除機台（名稱、機台代碼、型號備註）
- 顯示每台機台目前狀態（運行 / 停機 / 異常），狀態由 IoT 事件驅動

#### 4.1.3 IoT 元件管理

- 選擇機台後，檢視該機台所有 IoT 元件
- 新增 / 編輯 / 刪除元件，設定：
  - 元件名稱與代碼
  - 資料類型（Telemetry / Event / Command）
  - 數值單位（kgf、°C、mm、mm/s 等）
  - 上報頻率（秒）
  - 數值範圍（正常上下限，供告警規則使用）

---

### M2 — Dashboard（即時監控）

> **目的**：提供操作人員與管理層即時掌握產線狀態。
> **可見角色**：所有角色
> **資料更新**：Telemetry 折線圖與告警列表透過 WebSocket 即時推送；統計卡每 30 秒 Polling

#### 畫面佈局

```
┌─────────────────────────────────────────────────────────┐
│  站點狀態列                                               │
│  [錫膏印刷 ● 運行]  [AOI ● 運行]  [回流焊 ● 異常]  [組裝 ● 運行]  │
├──────────────────────────────┬──────────────────────────┤
│  即時 Telemetry 折線圖         │  告警列表（WebSocket 推送）  │
│  ┌ 站點切換 Tab ─────────┐   │  ● 高  回流焊溫度超標 12:32  │
│  │ 刮刀壓力 ───────────  │   │  ○ 低  站區濕度偏高  12:28  │
│  │ 印刷厚度 ───────────  │   │                          │
│  └───────────────────────┘   │  [查看全部告警]            │
├──────────────────────────────┴──────────────────────────┤
│  當前批號進度（Polling 30s）                               │
│  Lot-003  Unit 12/20  [站一 ●]  [站二 ●]  [站三 ◐]  [站四 ○] │
└─────────────────────────────────────────────────────────┘
```

#### 功能細節

- **站點狀態列**：各站即時狀態，點擊切換下方折線圖
- **Telemetry 折線圖**：依站點顯示所有機台的感測數值，支援多元件同時顯示，可調整時間窗口（最近 5 / 15 / 30 分鐘）
- **告警列表**：WebSocket 即時推入，依 Severity 顯示顏色（高：紅、低：黃），Operator 可 Acknowledge
- **批號進度卡**：顯示當前進行中批號、已完成 Unit 數、各站完成狀態

---

### M3 — 告警中心

> **目的**：管理告警規則、查詢歷史告警、設定通知方式。
> **可見角色**：所有角色（規則設定限 Admin）

#### 4.3.1 即時告警

- 全站告警的即時列表，WebSocket 推送
- 每筆告警顯示：時間、站點、機台、元件、觸發值、Severity
- Operator 可 Acknowledge（需填備註），Acknowledged 後標記處理人與時間

#### 4.3.2 歷史告警

- 篩選條件：站點、機台、Severity、時間範圍、是否已處理
- 列表檢視，可匯出 CSV
- 點擊單筆告警可查看觸發當下的感測數值上下文（前後 5 分鐘的 Telemetry）

#### 4.3.3 告警規則設定（Admin）

- 選擇 IoT 元件 → 設定觸發條件（數值 > / < 閾值，或連續 N 次超標）
- 設定 Severity（高 / 低）
- 設定通知方式：
  - 低：僅顯示於 Dashboard
  - 高：Dashboard + Telegram 推播

---

### M4 — 資料查詢

> **目的**：提供操作員查詢歷史資料，進行問題分析與製程復盤。
> **可見角色**：所有角色

#### 4.4.1 板件追溯（by unitSerial）

搜尋框輸入 unitSerial，顯示該片板件的完整跨站時間軸：

```
unitSerial: [PCB-2024-00123]  [查詢]

時間軸：
  ✅ 錫膏印刷   印刷機-01   10:00 上料 → 10:10 下料  操作員：王大明
     └─ 刮刀壓力 avg 2.1 kgf  印刷厚度 avg 0.15 mm  [展開原始數據]

  ✅ AOI 檢測   AOI機-01    10:12 上料 → 10:22 下料  操作員：李小華
     └─ 判定：PASS

  ⚠️ 回流焊    回焊爐-01   10:24 上料 → 10:34 下料  操作員：王大明
     └─ 溫度曾超標 +3°C（回流區）  [展開原始數據]  [查看相關告警]

  ✅ 最終組裝   組裝台-01   10:36 上料 → 10:46 下料  操作員：李小華
     └─ 扭力 OK  功能測試：PASS
```

- 每站可展開看完整原始 Telemetry 數值（時序圖 + 數值列表）
- 若該站有觸發告警，顯示連結可跳轉到對應告警記錄

#### 4.4.2 批號查詢（by LotID）

搜尋 LotID，顯示：

- 批號基本資訊（投料時間、關閉時間、Unit 總數）
- 批號內所有 Unit 的完成狀態總覽（表格）
- 每站的良率統計（AOI pass rate、最終組裝 pass rate）
- 批號內 AOI 複判記錄（機器判定 vs 人員複判比對）

---

### M5 — 系統設定

> **目的**：管理平台使用者與通知整合。
> **可見角色**：僅 Admin

#### 4.5.1 使用者管理

- 新增 / 編輯 / 停用使用者（名稱、帳號、角色）
- 列表顯示所有使用者與最後登入時間

#### 4.5.2 角色權限

- 顯示三個角色的功能權限對照表（唯讀，不可自訂角色）

#### 4.5.3 通知設定（Telegram）

- 設定 Telegram Bot Token 與通知 Channel ID
- 可發送測試通知驗證設定
